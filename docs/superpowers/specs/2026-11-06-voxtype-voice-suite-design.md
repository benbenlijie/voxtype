# Voxtype 语音输入整套方案设计

## 目标

以 Voxtype 为语音录入核心，把已经在本机验证或试用的中文文字处理、鼠标启动和识别结果回填整理成一个可安装、可分享的下游项目。保留上游来源和历史，并尽量让配套功能可单独启用或关闭。

## 组成

### 1. Voxtype 核心

- 以用户自己的 Voxtype 上游分支为项目基础，保留上游代码、许可证、版本历史和可追踪的上游远程。
- 不改变 Voxtype 原有录音、识别及右 Alt 快捷键行为。
- 不把本机为旧系统构建所需的 Vulkan、Cargo 或其他临时修改混入项目。

### 2. 中文文字处理配套

- 通过 Voxtype 已有的输出后处理入口接入，不改核心识别流程。
- 将识别文字从繁体转换为简体，再按需使用本地标点模型补充中文标点。
- 清理标点模型造成的数字、小数、时间、缩写和中英文标点间多余空格。
- 外部程序或模型不可用、处理失败或返回空结果时，回退到原始识别文字。
- 不把模型权重默认放进 Git；提供安装或下载步骤，并在公开前核对模型来源与许可。

### 3. 鼠标启动和回填配套

- 作为独立的可选服务调用 Voxtype 命令，不替换核心快捷键。
- 第一版按目前真实实现限定为 Linux 的 X11 桌面；把输入监听和平台相关操作隔离，方便以后增加其他桌面环境支持。
- 按住鼠标左键原地约 0.5 秒启动；启动前明显移动则取消等待。
- 录音开始后，鼠标距离按下位置超过 100 像素时取消，不识别、不回填。
- 松开鼠标结束录音并等待识别；不自动发送。
- 识别时尽量记录最初活动窗口与键盘焦点。目标无法安全确认时仅保留识别结果/剪贴板，不强行切窗或重新点击。
- 普通应用尝试一次 `Ctrl+V`；终端使用单独的粘贴方式。模拟粘贴不等于目标应用一定接收成功，不能承诺兼容所有程序。
- 保留锁屏、焦点变化、键盘输入、剪贴板归属和录音状态等保护；不得把聊天内容、识别原文或按键内容写入日志。

## 项目整理方式

- Voxtype 核心保留在仓库根目录。
- 中文处理、鼠标服务、安装器、示例配置和使用说明分别放在清楚命名的配套目录。
- 安装器用用户目录和系统现状动态确定路径，不写死本机用户名、Hermes 安装路径或 Node 版本。
- 安装、卸载、停用和恢复步骤均写入中文说明；鼠标服务由用户明确启用，不静默接管全局鼠标。
- 将单元测试、无障碍的模拟流程测试与真实桌面验收分开报告；模拟测试不代表真实应用兼容性。
- 排除模型文件、个人诊断日志、识别内容、缓存、编译产物、密钥和本机备份。

## 第一版不承诺

- 不承诺支持 Wayland、macOS 或 Windows 的全局鼠标监听；后续需按平台分别设计和验证。
- 不承诺能判断所有窗口中的具体输入框，也不承诺所有应用接受模拟粘贴。
- 不自动发送识别文字，不在不确定焦点时强行把文字写入某处。
- 不把本机某次成功测试扩大成所有用户、所有应用都已通过。

## 验收条件

1. 从干净检出状态能按文档安装；不依赖当前机器的绝对路径或隐藏文件。
2. 原有右 Alt 录音流程保持可用。
3. 中文后处理有简体、标点、空格修整、英文保留及失败回退测试。
4. 鼠标触发阈值、移动取消、松开结束、安全检查和终端粘贴方式均有测试。
5. 服务停用和卸载不会删除用户语音模型、Voxtype 配置或其他个人数据。
6. 文档明确列出 X11 范围、粘贴风险及尚未验证的应用，不宣称普遍兼容。
